# J288 / S288 模式切换与一拖多测试

## 模式切换修复

用户提供的 STM32 `firmware/App/protocol.c`、`protocol.h` 以及
Python `servo_demo.py` 均把工作模式放在每个控制帧中：0 为锁定，1 为 FOC。
位置、速度、力矩和阻尼控制是同一混合 FOC 的不同目标与 Kp/Kd 组合。
界面新增「工作模式」选择和「使能 FOC（零力矩 / 零增益）」操作；发送目标时也会按需完成使能。

2026-10-20 在 `/dev/ttyACM0`、ID 0 实机复现了反馈滞后一帧：

| 本次发送 | 立即收到的模式 | 原代码行为 |
| --- | --- | --- |
| 锁定 0 | 0 | 正常 |
| FOC 1，零力矩及零增益 | 0 | 误判未进入 FOC，立即停止 |
| 锁定 0 | 1 | 又误判停止未确认 |
| 再发锁定 0 | 0 | 确认锁定 |

修复后先用零力矩、零 Kp/Kd 确认模式，再发送实际目标。锁定也重复确认，
包含清除超时标志。切换有次数上限和时间预算；故障、超时保护及非正常工作模式仍会报错，
不会无限接受模式不符的反馈。持续控制时出现模式异常仍会停止。
单次目标的约 200 ms 计时从使能及目标发送成功后开始。

实机修复后零输出使能返回成功，反馈模式为 1；第一次 Stop 操作确认模式 0。
测试前后输出位置约为 4.81539 rad。测试未写入 ID 或 Flash 参数。

## 图形界面

1. 每台舵机分别设置不同的 ID，再接入同一单线总线并共地、供电。
2. 打开同一个 USB 串口，扫描 0–14，进入「一拖多测试」。
3. 选择 2–15 个 ID 和 1–120 秒时长，先点击「开始通信测试（锁定）」。
4. 如需运动，分别填写各 ID 的位置、速度、前馈力矩、Kp、Kd，再点击 FOC 测试。
   可分别使用当前位置，也可明确套用当前单机目标。
5. 查看各 ID 的发送/接收数、丢包率、超时、无效帧、实际 Hz、平均/最大延迟和最终锁定结果。
6. 结束后可导出 JSON 报告。全局 Stop / Ctrl+Enter 和「停止全部测试舵机」均停止全部成员。

多机测试先逐台确认锁定及健康状态，再以零输出逐台确认 FOC，最后才发送各自的目标。
通信测试只使用锁定模式，忽略运动输入。FOC 测试始终启用舵机通信超时保护。
单机目标和 ID 配置在多机测试期间不可执行；左侧切换参与测试的 ID 仅切换反馈显示。

每次命令都使用单个 ID，并等待该 ID 的有效反馈后才处理下一台。
不使用广播 ID 15，也不同时等待多台应答。各台命令依次发送，不保证硬件同步。
相同 ID 的物理设备无法可靠区分，需要先分别配置唯一 ID。

发送频率取自「通信与限制」中的目标频率。设备数量和 USB 往返时间会降低实际频率，
结果表显示测得频率和超出目标周期的次数。测试指标统计正式轮询阶段，
不包含预检、使能和最终锁定报文。报告中的末次反馈可由最终锁定反馈更新。

## 故障及退出

任一运动成员报告故障、触发保护、连续 3 次收不到有效反馈，或总线周期超过 500 ms，
会结束测试并对所有成员发送锁定指令。预检全部通过前不向任何成员发送 FOC。
界面心跳丢失 1.5 秒也会结束测试。

一台不应答不会阻止其他成员收到停止命令。尚未确认锁定的 ID 单独保留，
空闲时继续尝试；全局 Stop 可重试。它们全部确认前不允许重新使能或正常断开。
强制关闭时执行已有的有界清理。锁定成功后空闲监控继续轮询所有已发现的 ID。

## 命令行通信测试

以下命令只执行锁定模式通信测试，不启动 FOC、不写 ID、不保存 Flash：

```sh
# 明确指定多台 ID，测试 5 秒
cargo run --offline --manifest-path src-tauri/Cargo.toml \
  --example unitree_bus_probe -- /dev/ttyACM0 0,3,14 5

# 省略 ID 时，使用扫描发现的全部 ID；少于两台会说明原因并退出
cargo run --offline --manifest-path src-tauri/Cargo.toml \
  --example unitree_bus_probe -- /dev/ttyACM0
```

串口需要由一个程序独占；运行命令前先断开图形界面的串口连接。
