# 拉线底盘（HopeA3）

首页「原始 CAN 总线应用」中的独立 app，结合 MHF5010 拉线、方向编码器与
HopeA3 三轮底盘的真实 HexMeow 电机控制。独立 HopeA3 app 仍可单独使用。

## 参考版本与协议

A2 控制与编码器基于 `string_chassis` 的 **main / 20133accb224eed665c9308de05181e9a653c15e**。
A1 使用 **main / 5b3e7581da6ab6e792726a8ec7fe2d9ba8cbf6d5** 保留的分区电流算法，
并沿用该提交前 A1 运行器的归零电流降幅和停机顺序。两种模式均随工程编译。
源文件映射和适配范围见 [UPSTREAM.md](../src-tauri/crates/mhf-pull-cord/UPSTREAM.md)。

- MHF5010 / DHF50：Classic CAN 1 Mbps，8 字节标准帧，CAN ID 为 `0x140 + 电机 ID`。
- **A1 电流模式**通过 `A1 00 00 00 lo hi 00 00` 下发带符号的小端 i16。
  归零时向收线方向给定电流，实测收线速率进入距归零速度软上限 0.2 m/s 的区间后线性减小电流，达到上限时降至零。
  归零后沿用 A2 的实测线速判定。线速大于 `0.005 m/s` 时采用出线电流，小于 `−0.005 m/s` 时采用收线电流，
  两个阈值之间（含边界）采用静止电流。三档均向收线方向施力，并要求出线电流 ≤ 静止电流 ≤ 收线电流。
  从基础轻拉区末端到末端区起点，三档都按线长逐渐叠加「末端静止电流 − 静止电流」的差值。
  最终幅值四舍五入并限制在零到电流指令上限之间。
- **A2 速度模式**在每次显式启动时配置 RAM 速度 PID、最大速度与加速度。
  实测线速大于 `0.005 m/s` 采用出线限矩，小于 `−0.005 m/s` 采用收线限矩，中间采用静止限矩。
  按线长叠加末端提醒并按总限矩封顶。变化的限矩先写 `C1 1E` 并核对回包，再发送同限矩的 A2。
- 归零要求实测线速绝对值低于 `0.02 m/s` 连续 600 ms，默认超时 20 s。
- 角度或当前模式的运动反馈超过 150 ms、状态超过 400 ms 进入故障停机。
- A1 停机先发零电流，A2 停机先发零全局限矩和零速。随后均发送停止、关闭并读取状态确认。
  启动或停机失败时保留节点、所选模式与 CAN 会话，供再次停机。

CAN 协议 V2.36 第 9–10 页给出 A1 指令范围 ±2048，并说明驱动全局限矩不约束 A1。
MHF 接线手册第 13 页则将 A1 的有效调节范围写为 ±850（电压占空比）。本 app 采用 V2.36 的
原始指令单位，分别显示下发指令与反馈计数。实际电流与拉力需要按所用驱动固件和负载标定。

## 连接和使用

1. 在首页打开「拉线底盘（HopeA3）」。打开页面、加载参数、连接 CAN 均不会启动电机。
2. MHF5010 与方向编码器共用经典 CAN 接口。Linux 默认 `can1`，须先将接口配置为
   1 Mbps、FD 关闭并置为 UP。应用读取校验配置，不修改系统接口。
   USB-CAN 可填写 `gs_usb0` / `gs_usb1`，应用按 Classic 1 Mbps 打开。
3. 默认电机 ID 1，编码器节点十进制 16（`0x10`）。连接后向编码器发送定向 NMT Start，
   订阅位置、磁状态和心跳。编码器没有有效反馈时显示等待状态，不伪造角度。
   方向中心角默认 275°，来自本机已保存的装配配置。首次打开时从底盘保存配置或
   编译默认配置读取中心角。底盘启动或应用跟随参数后，显示中心与
   底盘运行参数同步；修改显示中心不能代替设置底盘的编码器中心参数。
4. 在「运行」中选择「A2 速度模式」或「A1 电流模式」，核对半径、收线方向及对应模式的参数后，点击「启动 / 归零」。
   模式选择只更新草稿。切换时先点击「停机并关闭电机」，确认关闭后即可选择另一模式并再次启动。
   「重新归零」使用同样的归零流程；「停机并关闭电机」也可在启动等待期间使用。
5. A1 可观察带符号的电流指令、反馈电流及实测线速。A2 可观察已确认的全局限矩、帧内限矩及目标速度。
   满电流与最大力矩映射参考分别用于显示各模式的指令或限矩占比。
6. 编码器固件零点需在拉线电机停止后显式设置；先核对产品身份，再写入、读回并检查
   新位置帧。该零点与拉线电机的机械止挡归零是两项不同操作。

切换工具、断开连接、关闭窗口均进入停机清理。普通断开未确认关闭时报告失败并保留会话。
拉线和底盘的两个接口作为同一应用共同占用 CAN，与其他原始 CAN 应用、分析仪和固件更新互斥。

## 拉线末端轨迹

单独连接拉线模块，在 A1 或 A2 模式下完成归零后，将手柄拉出，在同一平面内保持绳线拉直。
「拉线末端轨迹」会显示当前位置、移动轨迹和二维速度。出线口为原点，+X 沿设定的方向中心向外，
+Y 指向面朝 +X 时的左侧。坐标随出线口移动，描绘的是手柄相对装置的运动。

半径取归零后的卷筒多圈实测线长，两次多圈回读之间用实测出线速度补算位移。方向角取磁编码器
相对中心的偏角，逆时针为正。末端速度包含沿绳的收放速度和摆动产生的切向速度，因此固定线长
左右摆动也能测出圆弧。切向速度使用两帧磁编码器位置的实际接收时间和最短角差计算。

后端在拉线循环中计算当前点。图中保留最近 1,500 个轨迹点，包括各段的首尾点。
常规轨迹点最多每秒取 25 个，距上个绘图点移动至少 1 mm 时才追加，手柄静止时仍可查看已画出的轨迹。
角度、线速或线长过期，以及磁铁丢失时，实时点消失，图中保留已测路径。反馈恢复后另起一段。
停机后可以查看最后一次轨迹。重新启动、重新归零或应用新的方向中心角后，开始使用新的坐标基准。
点击轨迹卡片右上角的「清除轨迹」即可清空已记录的路径。运行中会从当前手柄位置继续绘制，
实时位置和速度持续更新。停机后也可以清除保留的路径。

### 只读反馈接口

- 前端调用 `api.pullCordEndpoint()`，对应 Tauri 命令 `pull_cord_endpoint`。返回最新的
  `CordEndpoint`，归零中、停机、故障或反馈过期时返回 `null`。
- Rust 消费者可在一次拉线运行中取得 `let trajectory = control.trajectory();`，
  在自己的循环内调用 `trajectory.latest()`。该句柄只读取本次运行的反馈，可直接供后续底盘控制使用。
- 曲线消费者可调用 `api.status(previousCursor)`，从 `trajectory.points` 读取增量样本，
  再将 `trajectory.cursor` 用于下次读取。首次读取或坐标基准变化时返回完整的保留窗口。
  清除轨迹时游标也会前进。将本地路径裁剪到 `retained_points` 个点，点数为零时清空。
  轨迹分段以 `frame_id` 和 `segment` 标识。

| `CordEndpoint` 字段 | 含义 |
|---|---|
| `frame_id`, `segment` | 坐标基准和连续采样段编号 |
| `time_us` | 本次拉线启动以来的单调采样时间，单位 µs |
| `center_deg` | 本次位置和速度使用的编码器中心角，单位 ° |
| `x_m`, `y_m` | 手柄在出线口局部坐标系中的位置，单位 m |
| `length_m`, `bearing_rad` | 补算到采样时刻的线长和相对 +X 的逆时针方位角 |
| `radial_speed_m_s` | 实测径向线速，出线为正、收线为负 |
| `velocity_m_s` | 局部速度 `[vx, vy]`，单位 m/s，每段获得第二个不同时间的方向样本前为 `null` |

## 真实底盘跟随

1. 将三个 **HexMeow** 底盘电机连接到另一个 CAN-FD 接口，节点为十进制 **21 / 22 / 23**，
   主机节点 10。Linux 默认 `can0`，USB-CAN 默认 `gs_usb1`。仲裁段 1 Mbps，数据段默认
   5 Mbps；Linux 接口需预先配置为 UP，界面数据段速率需与实际配置一致。
   拉线仍使用 Classic 1 Mbps，不能和底盘共用同一接口。
2. 点击「连接底盘」。此时只建立连接；先完成拉线归零，确认方向编码器反馈有效。
3. 选择「实时设备」、身后跟随 / 身前引导、前端 / 后端出线。使用身后跟随且启用步速同步时，
   可选「纵向步速同步（原模式）」或「全向步速同步」。点击「启动真机跟随」，按原收线动作发车。
   该操作复用 HopeA3 的固件识别、标定读取、MIT 初始化和 500 Hz 三轮控制。
4. 跟随核心以 100 Hz 运行。两种步速模式都用原纵向控制器计算前后速度。默认的纵向模式
   通过拉线偏角控制车身转向，横向指令为零。全向模式在发车后的身后步速同步阶段叠加横移，
   此时车身角速度目标为零。身前引导仍按拉线偏角转向。车身正角速度为逆时针，
   正编码器偏角为顺时针，可通过「左右方向反相」适配装配方向。
5. 步速同步、线长修正、长线制动、猛拉停车和收线确认重启基于参考逻辑。
   步速估计采用三个电机的真实速度反馈；界面展示目标速度、实测速度、位姿和各电机状态。
   「切换身前线长」在发车前和运行中均生效，包括已进入步速同步的身后跟随。
   实时线长达到阈值（例如本机配置的 1.0 m）时，优先进入切换制动；指令归零且
   实测纵向速度不超过 ±0.02 m/s 后，若线长仍达到阈值，则进入身前引导。
   恰好等于阈值时身前目标速度为零，超过阈值后按原身前线长 / 线速规则起步。
   制动中线长回摆或反馈缺失不会提前解除制动；停稳后按当前线长选择运行方向。
   切换制动不低于当前步速同步、停止线或已触发的猛拉制动；界面依次显示
   「切换制动」和「身前引导」，无需停机更改模式选择框。
   身前引导采用反向的左右转向映射（自动切换和直接选择均适用），切换制动结束后生效；
   「左右方向反相」、转向死区与角速度限幅继续生效。全向模式还会等待横向指令归零、
   实测横向速度降至 ±0.02 m/s 以内，再结束长线或切换制动。
6. 实时跟随增加「回收超速制动」：实测线速为负且收线速率**达到或超过**设定阈值时，
   优先制动并将转向目标归零，适用于身后、身前及步速同步。减速度取本 app 当前配置的
   普通、停止线、切换、自适应、猛拉、回放重启和步速同步减速度中的最大值
   （编译默认参数为 **3.0 m/s²**），不受基础加速度或线速滤波延迟影响。
   自动阈值取拉线模块已应用的 `retract_speed_m_s`（编译默认 **2.0 m/s**）。
   A2 将它用作收线目标速度，A1 将它用作底盘回收制动参考速度。也可取消勾选并填写独立阈值，点击「应用并保存参数」生效。
   线速提前回落仍会完成制动；指令归零、实测平移及转向停稳，且收线速率低于阈值的
   95% 后解除制动，清除旧跟随估计并按当前线长、线速重新跟随。持续快速回收时保持停车。
   界面显示「回收超速制动」、实际运行阈值及制动减速度；手动台架不启用此实时设备保护。
   旧版底盘配置缺少 `retract_brake_speed_mps` 时自动采用收线目标速度，数值覆盖和自动模式
   （`null`）均随底盘参数保存。

### 全向步速同步

发车后，手柄向车身左侧移动会产生正的横移指令，向右移动会产生负值。纵向和横向可以同时生效，
也可以单独横移。界面的「指令前进 / 左移 / 转向」与「实测前进 / 左移 / 转向」可对照观察三个分量。

横向步速取三轮实测横向速度加上末端相对横向速度，并用实测角速度补偿车身转动对末端速度的影响。
转动补偿以出线口近似底盘平移参考点。前端出线时，面朝出线方向的左侧对应车身左侧，
后端出线时对应车身右侧。「左右方向反相」可翻转拉线反馈的横向符号。
当人和车同速横移时，末端相对速度接近零，实测轮速仍能维持同步。

控制器记录接入同步时手柄的横向位置。手柄偏离该位置超过「允许浮动」后，按步速参数中的回调增益
和速度上限修正横向偏差。横向估速使用「步速滤波」。斜行时按合成速度限制跟随速度、底盘速度和每次速度变化。
末端速度暂缺时，横向目标回零。新轨迹段、重新标定中心角会重新取横向基准，清除显示轨迹可继续跟随。
猛拉停车、长线制动、切换制动和回收超速制动均优先于横移。

手动测试与参考工程一致：选择「手动测试」并「使能手动台架」后仍保持零指令；
编辑线长、线速、角度只改变草稿，点击「应用手动输入」才执行，并持续到再次应用、
「释放手动输入」或停机。此模式直接驱动真实底盘，无需拉线设备。

「立即停机 / Esc」停止并确认三个底盘电机失能，不停止拉线模块。
拉线的「停机并关闭电机」、重新归零、主连接断开、切换工具或关窗会同时停止底盘。
实时拉线反馈或编码器角度超过 150 ms、拉线运行会话失效、底盘反馈异常或跟随循环超时
均停止跟随；恢复反馈不会自动重启。初始化或停机失败时保留会话，先再次停机确认才能启动。

运行中的参数须点击「应用并保存参数」生效；停止时「保存配置」仅保存下次启动模板，
位于应用配置目录的 `pull-chassis.json`。输入来源、跟随模式、步速同步方式、出线侧和左右方向反相须停机修改。
旧配置缺少 `pace_motion` 时采用原纵向模式（`steering`），全向模式保存为 `omni`。
当前编译默认参数采用 2026-11-17 本机保存的配置：实时设备、身后跟随、后端出线，
步速同步开启，目标线长 1.2 m，停车余量 0.2 m，编码器中心 275°。
身后启动 / 分界 / 停车 / 身前切换线长分别为 0.7 / 0.9 / 1.39 / 1.6 m。
最高跟随、负速度参数和底盘线速度上限均为 1.6126842288427603 m/s
（显示约 1.6127 m/s，对应 154 mm 轮径的 200 rpm）。
保留参考控制器的 200 RPM 调参范围，按 HopeA3 的 154 mm 轮径
换算为约 1.613 m/s；转向角速度默认上限 1.5 rad/s。电机 KD 和限矩沿用 HopeA3 默认值，
详见 [HopeA3 协议与几何](hopea3.md)。

## 参数

本机没有保存配置时和「恢复默认」均采用随程序编译的完整配置快照：

- [拉线默认参数](../src-tauri/defaults/pull-cord.json)：来自本机 `pull-cord.json` 的 `pull_cord` 对象。
- [HopeA3 底盘默认参数](../src-tauri/defaults/pull-chassis.json)：以本机完整的 `pull-chassis.json` 为基础，按要求将直行限速同步为 200 rpm 对应的线速度。

两份 JSON 通过 Rust `include_str!` 编入程序，其他电脑首次编译运行无需复制本机配置文件，
也不依赖相邻的 `string_chassis` 仓库。已有本机保存配置始终优先；「恢复默认」只更新草稿，
保存后才覆盖本机模板。控制协议与算法以前述参考主分支为基础，并扩展了运行中的
身前阈值切换；原始上游默认文件保留用于追溯。

首次启动和缺少模式字段的旧配置默认选择 A2。显式「保存到本机」会保存所选模式和两套参数。
默认 A1 的出线 / 静止 / 收线基础电流为 **100 / 150 / 200 raw**，归零电流为 **400 raw**，
末端静止电流为 **600 raw**。因此到达末端区时三档分别为 **550 / 600 / 650 raw**。
电流指令上限和满电流参考均为 **2048 raw**。各档电流、归零及末端静止电流均可在线应用。电流指令上限与满电流参考需停机修改。

旧 A1 配置会保留原基础电流作为静止和收线电流，出线电流取原基础值的一半并向下取整。
新参数分别保存为 `payout_current_raw` 和 `retract_current_raw`。以下为默认 A2 和公共参数。

| 参数 | 初始值 |
|---|---:|
| 卷筒半径 / 总线长 | 0.026 m / 3 m |
| 收线方向 | 负向 |
| 归零 / 收线速度 | 2.0 / 2.0 m/s |
| 出线 / 静止 / 收线限矩 | 100 / 150 / 200 raw |
| 归零 / 末端 / 总封顶 | 200 / 200 / 300 raw |
| 映射参考 | 2048 raw |
| 速度 Kp / Ki / Kd | 20 / 0 / 0 |
| 加减速斜率 | 2500 °/s² |

A2 归零和收线目标速度的可设置上限为 **1000 rpm**，按当前卷筒半径换算成线速度。
26 mm 半径对应约 **2.723 m/s**。此上限依据 CAN V2.36 第 15 页的 `Speed Limit (0x20)`，
最大原始值 600000，单位 0.01 °/s，即 6000 °/s。默认归零 / 收线速度仍为 2.0 / 2.0 m/s。

「应用到运行」提交当前草稿，运行状态在对应模式的指令收到回包后更新。A2 还会核对必要的 RAM 参数回包。
「保存到本机」仅保存下次使用的模板，不改变运行参数或启动电机，文件位于应用配置目录的
`pull-cord.json`。「恢复默认」仅修改表单草稿。卷筒半径和收线方向需停机修改。

保存范围包括拉线控制参数、底盘跟随与步速参数、步速同步方式、跟随模式、输入来源、出线侧、左右方向反相、
中心角、速度和加速度限制，以及三个电机的 KD 和限矩。**关闭时不会自动保存未提交的草稿**：
拉线需点击「保存到本机」，底盘需点击「保存配置」或「应用并保存参数」。
CAN 接口、数据段波特率、拉线电机及编码器节点选择、手动测试临时输入不属于上述保存配置；
首次打开仍使用平台连接默认值。使能状态、归零过程和位姿不恢复，必须显式连接并启动。
