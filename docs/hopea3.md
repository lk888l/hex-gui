# HopeA3：HexMeow 三轮底盘

HopeA3（原始电机）使用与 Motor Control 相同的 `hex-motor 0.3.2`
`MeowMotorManager`。三台底盘电机必须运行 HexMeow 固件，并通过 SDK 对
`0x1018` 的完整型号识别；旧 HEX / CiA402 身份会被拒绝。

节点固定为十进制 **21、22、23**，主机固定为 **10**，连接时开启主机心跳。
轮径 154 mm、轮心圆直径 648 mm、轮序和键盘/手柄控制沿用原有底盘配置。
速度与反馈均为减速器输出轴 Rev/s，不额外乘齿轮比。

## 控制与反馈

底盘以 500 Hz 发送一帧 24 字节 CAN-FD RPDO（COB-ID `0x18A`）。每台电机
占用 8 字节，其他电机的字段由 SDK 同款 `0x3000:03` 占位映射跳过：

| 字段 | HexMeow 对象 | 格式 |
| --- | --- | --- |
| 轮速 VDES | `0x4102:02` | f32，Rev/s |
| 速度增益 KD | `0x4102:05` | u16，0–65535 |
| 全局输出力矩限幅 | `0x4572:00` | u16，0–1000‰ |

初始化显式设置 `0x4103:01=0`，选择非压缩 MIT。SDK 写入零目标
（PDES/VDES/TFF/KP/KD 均为 0），再通过 `0x4401=4` 使能，并等待新的 TPDO2
确认。`0x4102:06` 的 KP/KD 结果限幅固定为 1000‰；实际输出限幅由每帧的
`0x4572` 控制。三台全部初始化完成前，输出力矩限幅保持 0。

KD 输入单位为 Nm·s/rad，线缆值为
`round(KD × 2π / 0x4102:07)`，与 Motor Control 一致。
缺失、非有限或非正的 Kp/Kd 系数会阻止启动，不使用猜测的默认系数。

SDK 配置 TPDO1 为 500 Hz，读取 Q8.24 位置、设备时间戳和力矩千分比，
由 SDK 估算轮速；TPDO2 提供 HexMeow 模式、详细错误码与温度。
力矩显示复用 Motor Control 的 `0x4001` 工厂标定解释与换算：
`物理 Nm = 反馈千分比 / 1000 × 峰值 Nm / torque_factor`。
明确未标定时采用 1.0；读取失败会报错。工厂力矩系数不乘入 KD 或原始域限幅。

## 运行与恢复

- 任一电机掉线、反馈过期、离开 MIT、发生错误或身份会话变化，整车发送零输出，
  清除旧速度指令，并暂停不完整反馈的里程计积分。
- 重新初始化单台电机期间，整车暂停输出；重新读取该电机的系数与会话信息，
  完成后等待新的驾驶指令。
- CAN 发送失败会保持禁止运动，需要停止后重新启动。
- 停止先结束 500 Hz 任务、发送零帧，再逐台调用 HexMeow `disable()`，确认失能。
  任一确认失败都保留会话和停止按钮，可重试；断开连接也遵守此流程。
- 退出原生窗口使用应用的安全清理流程。

独立的拉线控制（MHF5010）app 仍按 `string_chassis` 主分支的瓴控协议运行，
与本次底盘电机协议迁移无关。

## 验证

`cargo test --lib hopea3` 通过模拟 CAN 总线运行真实 SDK，覆盖三台初始化、
共享映射、反馈、旧身份拒绝、标定读取失败、失能重试、反馈中断及重新初始化。
`test/hopea3.test.ts` 覆盖驾驶入口、故障恢复与停机失败时的界面状态。
模拟测试不替代连接实际三轮底盘后的硬件验证。
